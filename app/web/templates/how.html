How Aegis works

Aegis is a fraud and risk engine, built in loops. It takes in transactions through a REST API, scores each one against that customer's own behaviour, opens an incident when the risk is high, and gives an analyst the evidence to decide. The model assists; the analyst decides.

What happens to each transaction

ValidateStrict schema: positive amounts, time-zone-aware timestamps, no unknown fields, no duplicates.POST /v1/transactions
Load historyThe customer's last 200 earlier transactions.PostgreSQL
Compute features15 numbers comparing this payment with what is normal for this customer.app/features.py
ScoreLogistic regression gives a risk score from 0 to 1, plus each feature's push.app/model.py
Open an incidentAbove the threshold: an incident with severity, evidence and an audit trail.incidents, incident_events
Analyst decidesConfirm, dismiss or reopen, with notes. Every action is appended to the audit trail.POST /v1/incidents/{id}/actions

How it's built

Everything is Python. FastAPI serves both the JSON API and these pages, which are rendered on the server with Jinja2 templates; there is no JavaScript. Data lives in PostgreSQL through SQLAlchemy, with Alembic migrations. The model was trained with scikit-learn and exported as plain numbers, so the app scores with a dot product and needs no machine-learning libraries at run time. GitHub Actions runs the tests against a real database on every change.
